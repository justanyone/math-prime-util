## Native-only names

Each group gives the value, the reason, and the names. `n.a.` groups come first.

### integer operators

`n.a.`, 26 names. Plain integer arithmetic, comparison, shifts and parity on `i128`. num-bigint's operators (`+ - * / % << >>`, `pow`, comparison) and the num-integer `Integer` trait it implements (`div_floor`, `mod_floor`, `div_rem`, `div_ceil`, `is_even`, `is_odd`, `is_multiple_of`) do the same on `BigUint` and `BigInt`; a wrapper adds nothing.

`absint`, `add1int`, `addint`, `cdivint`, `cdivrem`, `cmpint`, `divint`, `divrem`, `fdivrem`, `is_congruent`, `is_divisible`, `is_even`, `is_odd`, `lshiftint`, `modint`, `muladdint`, `mulint`, `mulsubint`, `negint`, `powint`, `rashiftint`, `rshiftint`, `signint`, `sub1int`, `subint`, `tdivrem`

### bit operations

`n.a.`, 12 names. num-bigint's `&`, `|`, `^`, `bit`, `set_bit`, `count_ones`, `trailing_zeros` and `trailing_ones` do these on `BigUint`; `bitnot` needs a fixed word width, which `BigUint` does not have.

`bitand`, `bitandnot`, `bitclear`, `bitflip`, `bitnot`, `bitor`, `bitscan0`, `bitscan1`, `bitset`, `bittest`, `bitxor`, `hammingweight`

### generic over the element type

`n.a.`, 14 names. Generic over the element type `T`: these already take `BigUint` elements.

`formultiperm`, `forsetproduct`, `vecall`, `vecany`, `vecequal`, `vecextract`, `vecfirst`, `vecfirstidx`, `vecnone`, `vecnotall`, `vecpairwise`, `vecreduce`, `vecslide`, `vecwindow`

### combinatorial enumeration

`n.a.`, 6 names. Visit every combination, composition, derangement, partition or permutation. The number of objects, not the integer width, bounds `n` (sizes are `usize`); `lastfor` stops a loop and takes no integer.

`forcomb`, `forcomp`, `forderange`, `forpart`, `forperm`, `lastfor`

### real functions

`n.a.`, 11 names. Real-valued: an `f64` argument or result, so the integer backend does not apply (MPU's Math::BigFloat precision path is not ported).

`bernreal`, `bestrational`, `chebyshev_psi`, `chebyshev_theta`, `ExponentialIntegral`, `harmreal`, `inverse_li_nv`, `LambertW`, `LogarithmicIntegral`, `RiemannR`, `RiemannZeta`

### already any size

`n.a.`, 2 names. Already unbounded: `Pi` returns as many digits as asked as a `String`, and `sumdigits` reads a digit string of any length.

`Pi`, `sumdigits`

### generator state

`n.a.`, 12 names. Seed, generator state and raw random output: fixed-width words, `f64`, bytes, or a shuffle or sample of the caller's slice, by definition.

`csrand`, `drand`, `entropy_bytes`, `irand`, `irand32`, `irand64`, `rand`, `random_bytes`, `randperm`, `shuffle`, `srand`, `vecsample`

### configuration

`n.a.`, 4 names. Process settings and the shared sieve cache; `prime_precalc` takes a sieve size held in memory.

`prime_get_config`, `prime_memfree`, `prime_precalc`, `prime_set_config`

### not in MPU 0.75

`n.a.`, 1 names. Not in Math::Prime::Util 0.75, so there is nothing to port.

### rejected past 2^63 by MPU

`n.a.`, 2 names. MPU 0.75 croaks ("n must fit in native signed integer") for `n` above 2^63-1, in its pure-Perl path as in C, so there is no big-integer result to port. The native forms return `None` (`hclassno`) or panic (`integer_complexity`) there; `tests/compat_bigint_oneint.rs` checks both against the oracle.

`hclassno`, `integer_complexity`

### impractical past 2^64

`n.a.`, 3 names. MPU 0.75 accepts a big `n`, but its pure-Perl path does not finish (each runs past a 30 s limit on a 65-bit input). `farey` first takes the totient sum up to `n`, and the sequence has about 0.3n^2 terms. `is_catalan_pseudoprime` reduces to the full binomial(n-1, (n-1)/2), primes included. `is_pillai` steps v = 8, 9, ... through v! mod n, so a prime `n` takes more than 2^64 steps; only `n` below 23 or with a factor 2, 3, 5 or 7 returns at once (zero), which the native forms match at the 64-bit edge.

`farey`, `is_catalan_pseudoprime`, `is_pillai`

### nth semiprime and prime power past 2^64

`n.a.`, 2 names. MPU 0.75 finds these from exact semiprime and prime power counts. Past the native range (an index above `MPU_MAX_SEMI_PRIME_IDX` or `MPU_MAX_PRIME_IDX`) those counts need prime counts near or past 2^64, and MPU's own Perl path does not return: `nth_prime_power(425656284035217744)` gave no result in 30 minutes, and `nth_semiprime(1701748900850019778)` none in 10 minutes. A `BigUint` form could not finish either. The native forms return MPU C's boundary values there (0 and the largest 64-bit prime); `bigint::family_nth` returns `None` for `nth_almost_prime(2, n)` and `nth_omega_prime(1, n)` past them.

`nth_prime_power`, `nth_semiprime`

### lucky, Ramanujan and twin-prime sieves

`n.a.`, 9 names. MPU 0.75 itself cannot answer these past 2^64: its XS code takes native integers only, and its pure-Perl path sieves from the start. `lucky_numbers`, `lucky_count` and `nth_lucky` sieve every lucky number up to about the argument, `nth_twin_prime` lists the twin primes from 2, and `is_ramanujan_prime`, `ramanujan_primes`, `ramanujan_prime_count` and `nth_ramanujan_prime` list the Ramanujan primes from 2. Measured on 2^64 and nearby (25 s, 4 GB): `nth_ramanujan_prime` croaks (float arithmetic on `Math::BigInt` gives NaN), `is_lucky` returns 0 at once only when its mod 2, 6 or 63 pretest rejects `n` and croaks the same way for other `n`, and the others run out of time or memory. The native forms answer to the `u64` limits of MPU's C code; `tests/compat_native_top_lucky.rs` checks `is_lucky`, `is_ramanujan_prime`, `nth_twin_prime` and `nth_ramanujan_prime` against MPU just below 2^64.

`is_lucky`, `is_ramanujan_prime`, `lucky_count`, `lucky_numbers`, `nth_lucky`, `nth_ramanujan_prime`, `nth_twin_prime`, `ramanujan_prime_count`, `ramanujan_primes`
